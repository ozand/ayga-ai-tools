# ayga-ai-tools — проектный план

## Статус

Начальная рабочая копия создана в `T:/Code/Chrome_Extension/ayga-ai-tools` на основе публичного репозитория `hamelsmu/claudesave`.

Это отдельный Git-репозиторий. Исходный remote пока указывает на upstream-репозиторий; публикация собственного fork или изменение remote не выполнялись.

## Цель проекта

Создать Chrome Extension для экспорта текущего Claude Artifact в Markdown с сохранением исходного содержимого:

- обычный текст и Markdown-разметка;
- Mermaid как fenced code block с языком `mermaid`;
- остальные блоки кода с исходным языком;
- без преобразования диаграмм в изображения;
- без выполнения содержимого Artifact.

Экспорт должен относиться только к отображаемому пользователю Artifact, а не к скрытым, историческим или несвязанным документам.

## Что взято из claudesave

Подходящими повторно используемыми частями считаются:

- Manifest V3-структура Chrome Extension;
- разделение content script и background service worker;
- механизм кнопки и обмена сообщениями между частями расширения;
- локальная генерация и копирование Markdown;
- общая модель преобразования данных Claude в Markdown.

## Что в upstream не решает задачу Artifact

Текущая копия upstream ориентирована прежде всего на сохранение разговоров Claude:

- content script работает на `https://claude.ai/*`;
- service worker перехватывает chat conversation API через `webRequest`;
- данные сохраняются в `chrome.storage.local`;
- экспортируется разговор или Gist.

В текущем manifest нет отдельного покрытия `*.claudeusercontent.com` и нет `all_frames: true`. Поэтому расширение не получает content script внутри cross-origin iframe Claude Artifact.

Кроме того, upstream предполагает GitHub PAT для сохранения Gist. Для этого проекта такой способ не является обязательным и не должен включаться в Artifact Markdown export без отдельного решения.

## План архитектуры

### 1. Контентные скрипты в двух контекстах

Добавить отдельный content script, который запускается:

- на оболочке Claude Artifact (`https://claude.ai/code/artifact/*`);
- внутри iframe Artifact (`https://*.claudeusercontent.com/*`).

В manifest потребуется минимальное host-покрытие для этих доменов и `all_frames: true`. Не следует использовать `<all_urls>` без необходимости.

### 2. Обмен сообщениями

Родительская часть расширения добавляет кнопку экспорта и отправляет команду во фрейм.

Фрейм:

1. проверяет, что команда пришла от ожидаемого родителя;
2. извлекает текущий DOM Artifact;
3. преобразует его в Markdown;
4. отправляет только результат и безопасные метаданные обратно.

Каждый обработчик должен проверять:

- `event.source`;
- ожидаемый `event.origin`;
- форму сообщения;
- ограничение на текущий Artifact/frame.

Нельзя принимать произвольные cross-origin сообщения и нельзя выполнять пришедший HTML, JavaScript или Mermaid-код.

### 3. Markdown-конвертер

Конвертер должен обрабатывать:

- `h1`–`h6`;
- абзацы и переносы;
- списки;
- ссылки;
- emphasis;
- цитаты;
- таблицы;
- `pre > code`;
- Mermaid-контейнеры и их исходный текст;
- изображения как Markdown-ссылки, если они являются частью содержимого.

Для блока кода нужно сохранять текстовое содержимое, а не `innerHTML`. Для Mermaid нужен fenced block:

````markdown
```mermaid
flowchart TD
    A --> B
```
````

SVG, который является только результатом рендеринга без исходного Mermaid-текста, нельзя надёжно преобразовать обратно в Mermaid. Такой SVG не должен ошибочно выдаваться за исходный код.

### 4. Скачивание

Markdown создаётся локально:

- `Blob` с MIME-типом `text/markdown;charset=utf-8`;
- локальный object URL;
- временная ссылка с расширением `.md`;
- удаление ссылки и освобождение object URL после скачивания.

Не сохранять в файл:

- cookies;
- токены;
- auth headers;
- временные tokenized URL;
- данные других вкладок или Artifact.

## Сценарий ручной проверки

До публикации или упаковки проверить в Chrome:

1. Загрузить Artifact с обычным текстом.
2. Добавить/открыть Artifact с Mermaid-диаграммой.
3. Проверить несколько блоков кода с разными языками.
4. Нажать экспорт из оболочки Claude.
5. Убедиться, что не происходит перехода на tokenized iframe URL.
6. Проверить скачанный `.md`.
7. Убедиться, что Mermaid находится внутри ` ```mermaid `.
8. Убедиться, что кодовые блоки остаются fenced blocks с языковыми маркерами.
9. Проверить ошибку при отсутствии доступного frame/content script.
10. Проверить консоль расширения на отсутствие секретов и лишнего содержимого.

## Открытые технические вопросы

- Точные селекторы текущего Artifact DOM могут меняться Claude.
- Нужно определить стабильный способ отличить контент Artifact от shell UI.
- Нужно проверить, доступен ли исходный Mermaid-текст в DOM или он иногда представлен только SVG.
- Нужно определить, будет ли кнопка размещаться в shell, popup расширения или обоих местах.
- Нужно решить, нужен ли отдельный экспорт разговора, или проект ограничивается текущим Artifact.
